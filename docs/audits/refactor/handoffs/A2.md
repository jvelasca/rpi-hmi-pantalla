## Decisiones tomadas
1. **`plugins = ["pydantic.mypy"]` NO funciona en este entorno** y por eso se retiró. `import pydantic.mypy` lanza `ImportError: cannot import name 'ExpandTypeVisitor' from 'mypy.expandtype'` (pydantic 2.12.5 vs mypy 1.19.1; instalación mypy mixta/compilada). Consecuencias verificadas empíricamente: el plugin no reconoce los `Field(default=...)` dentro de `Annotated` (los `Missing named argument` persisten) y además introduce un falso `no-redef` en `DeviceConfig.kwargs`.
2. **Solución alternativa (sin plugin):** convertir los campos con default de `Annotated[X, Field(default=...)]` a `X = Field(default=...)`. mypy entiende este patrón de forma nativa (verificado con probe). Cambio puramente de anotación, runtime idéntico (pydantic v2 trata ambos igual).
3. **Stubs:** se usó `# type: ignore[import-untyped]` para `yaml` y `paramiko` en vez de añadir `types-PyYAML`/`types-paramiko`. Motivo: no están instalados y solo añadirlos a `dev` no arreglaría mypy sin reinstalar; el ignore es autocontenido. `# type: ignore` DEBE ir como primer comentario de la línea (si va detrás de `# noqa: F401`, mypy no lo reconoce).
4. **`_client`/`_sftp` como `Any`:** paramiko carece de stubs y se importa de forma lazy; tiparlos `object` producía `union-attr`/`attr-defined`. `Any` es la opción de anotación correcta sin cambiar el import lazy.

## Riesgos / pendientes
- **Incompatibilidad pydantic↔mypy:** si el equipo quiere recuperar `pydantic.mypy`, hay que alinear versiones (p. ej. reparar/reinstalar mypy compilado o ajustar pydantic/mypy). Hasta entonces, el patrón `= Field(...)` cubre el caso.
- Los campos con default de otros modelos (`LedState.gpio_pin`, `ButtonState.press_count`, `DisplaySettings`, `SystemStatus.websocket_clients`, `StaticIpRequest.dns`, `ClientMessage.*`, `DeviceConfig.pin/kwargs`) NO se convirtieron porque siempre se construyen con valores explícitos o vía `model_validate`; si en el futuro se construyen omitiendo el default, mypy lo marcará y habrá que convertirlos igual.
- El `RuntimeWarning` de pytest es preexistente y no fue introducido por este workstream.
