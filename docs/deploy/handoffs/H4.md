## Fragmentos exactos añadidos

Nuevo job `security` (insertado entre `type-check` y `frontend`):

```yaml
  security:
    name: Security audit (pip-audit + bandit)
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Set up Python
        uses: actions/setup-python@v5
        with:
          python-version: "3.11"

      - name: Install Python dependencies
        run: |
          python -m pip install --upgrade pip
          pip install -r backend/requirements.txt
          pip install -r display/requirements.txt

      - name: Audit Python dependencies (pip-audit)
        run: |
          pip install pip-audit
          # Audita el fichero de requisitos; si pip-audit falla (p. ej. por la
          # versión de Python en uso), cae al modo sin argumentos que audita el
          # entorno ya instalado.
          pip-audit -r backend/requirements.txt || pip-audit

      - name: Run bandit static security analysis
        run: |
          pip install bandit
          # --severity-level medium: solo se bloquea el CI con hallazgos de
          # severidad media o alta; los de severidad baja se informan pero no
          # impiden el merge. Se excluyen los tests de backend y display.
          bandit -r backend/app display --exclude backend/tests,display/tests -q --severity-level medium
```

Nuevo paso en `frontend` (entre `Install dependencies` y `Run frontend tests`):

```yaml
      - name: Audit npm dependencies
        run: |
          cd frontend
          # Falla solo con vulnerabilidades altas/críticas; las moderadas no bloquean.
          npm audit --audit-level=high
```

## Decisiones tomadas
- Se usó `--severity-level medium` en vez de `-lll`: el help de bandit 1.9.4 define
  `-lll` como **HIGH** únicamente (y `-ll` como MEDIUM). Para que falle solo con
  hallazgos **medio/altos** (objetivo del encargo), `--severity-level medium` es la opción
  inequívoca y documentada.
- `pip-audit` usa `-r backend/requirements.txt` como entrada, con fallback `|| pip-audit`
  (audita el entorno instalado) si la resolución falla por versión de Python.
- `npm audit --audit-level=high`: solo vulnerabilidades altas/críticas bloquean; las
  moderadas no. Colocado ANTES de los tests/build para fallar pronto.
- No se añadió `[tool.bandit]` a `backend/pyproject.toml` para minimizar cambios: la
  exclusión de tests se hace declarativamente con `--exclude backend/tests,display/tests`.

## Riesgos / pendientes

  `bandit` (`B104` y `B601`). No se han suprimido (`# nosec`) ni corregido porque esos

- `pip-audit` puede fallar en CI si la versión de Python del runner no es compatible con

- `npm audit` depende de la base de datos de `npm`; un fallo de red en CI haría fallar el
  paso (comportamiento aceptable para una auditoría).
