# Handoff H1 — Unificar autenticación REST + WebSocket

## Resultado
Completado (no parcial). Autenticación unificada en un único módulo
`backend/app/api/deps.py` con dos dependencias, y aplicada de forma consistente a
los mutadores HMI, al endpoint WebSocket `/ws` y a los routers `/admin/*`
(SSH y deploy). Eliminada la duplicación de `_verify_api_key` en `ssh.py` y
`deploy.py`. CORS expone `X-API-Key`. Mensaje de `config.py` corregido.
Documentación (§2/§3 de `docs/SECURITY.md`) y tests actualizados.

- `require_admin_api_key` → respeta `SECURITY_MODE` (mutadores HMI/red).
- `require_admin_api_key_always` → exige key siempre; 503 si `ADMIN_API_KEY` vacía (`/admin/*`).
- `WS /ws`: en `protected`, acepta loopback (`127.0.0.1`/`::1`/`localhost`) sin key;
  el resto exige `X-API-Key` (rechazo con close code `4401` sin llamar a `accept()`).

## Decisiones tomadas
- El núcleo de comparación (`_require_matching_key`) se compartió entre las dos dependencias, manteniendo intacto el contrato de `require_admin_api_key` (en `local` retorna sin exigir; en `protected` exige key con 401).
- `require_admin_api_key_always` replica el comportamiento del antiguo `_verify_api_key`: 503 si no hay key configurada, 401 si no coincide. Esto preserva los asserts de `test_integration.py` (`status_code in (401, 403)` / `503`).
- WebSocket rechazado con `await websocket.close(code=4401)` **sin** llamar antes a `accept()` (Starlette 0.50.0 lo tolera; el `TestClient` lo observa como `WebSocketDisconnect(code=4401)`).
- Búsqueda de `X-API-Key` en el handshake case-insensitive y vía `Mapping` (cubre `Headers` de Starlette y dicts).
- `POST /api/settings/display` se dejó **sin auth** (decisión del coordinador; lo usa el display local). Documentado en `docs/SECURITY.md`.
- Los decoradores de `ssh.py`/`deploy.py` se reformatearon a multi-línea (E501) por el nombre más largo de la dependencia; se conservaron los `# noqa: B008`.
- Los tests de auth fijan el modo con `monkeypatch` sobre el singleton `backend.app.config.settings` (no se tocó `conftest.py`).

## Riesgos / pendientes
- `WS /ws` usa close code `4401` (no estándar). Si algún cliente WS (frontend SolidJS) no lo interpreta bien, se recomienda cambiar a `1008` en `ws.py` (comportamiento de rechazo idéntico).
- En `protected` con `ADMIN_API_KEY` vacía, los clientes WS no-loopback quedan rechazados (los mutadores REST devuelven 401, `/admin/*` devuelve 503). Confirmar que el display local siempre conecta desde loopback.
- `POST /api/settings/display` sigue sin auth por decisión explícita; revisar en una auditoría posterior.
- El warning de `test_state_manager.py` (coroutine no awaited) es preexistente y no está relacionado con este cambio.
